# modem — резервный интернет через LTE-модем

> **Сейчас** Wi-Fi Pi раздаёт свою точку доступа (`../network`), и модем — единственный канал
> в интернет. Сторож это видит (`wifi_mode: hotspot` в состоянии) и Wi-Fi не проверяет. Схема
> «Wi-Fi основной, модем резерв» ниже снова заработает, если вернуть Pi в домашний Wi-Fi.

Основной интернет у Pi — Wi-Fi. Запасной — USB-модем **Huawei E3372s** (HiLink, прошивка 22.300,
разлочен, SIM МТС). Модем сам держит LTE-подключение, для Pi он выглядит как сетевая карта
(`cdc_ether`, обычно `eth1`), его веб-интерфейс — `192.168.8.1` (доступен только с самой Pi).

## Как устроено

1. **NetworkManager**, профиль `lte-modem` (привязан к MAC модема — `nmcli -g 802-3-ethernet.mac-address connection show lte-modem`):
   статический адрес `192.168.8.100/24`, шлюз и DNS `192.168.8.1`, **метрика 700**.
   У Wi-Fi метрика 600, так что обычно всё идёт через Wi-Fi. Если Wi-Fi пропадёт совсем,
   его маршрут исчезнет и трафик сам уйдёт в модем. (DHCP на модеме выключен, поэтому адрес статический.)
2. **Сторож `internet-failover`** (`failover.py`, systemd) — для случая, когда Wi-Fi подключён,
   а интернета через него нет (упал провайдер, завис роутер). Каждые 10 с проверяет доступ отдельно
   через Wi-Fi и через модем (ping 8.8.8.8 / 77.88.8.8 / 1.1.1.1, при неудаче — HTTP generate_204).
   3 неудачи подряд через Wi-Fi → модему ставится метрика 50 (он основной). 3 удачи подряд → обратно 700.
   Меняется только текущая активация (`nmcli device modify`), после перезагрузки всегда Wi-Fi.
   Состояние — `/run/internet-failover/state.json`, его показывает панель (доска «Интернет»).

Трафик на проверки через модем — пара ping-пакетов раз в 10 с, порядка 1–2 МБ в сутки.

## Управление

- Панель → главная → доска **«Интернет»**: через что сейчас идёт интернет, оператор, тип сети, сигнал
  (RSRP/SINR), скорость и трафик модема; мобильные данные вкл/выкл, режим сети (Авто / только 4G/3G/2G),
  переподключение, перезагрузка модема.
- Командная строка:

```sh
sudo systemctl status internet-failover      # сторож
journalctl -u internet-failover -f           # переключения
cat /run/internet-failover/state.json         # текущее состояние
ip route show default                         # маршруты: у кого метрика меньше — тот основной
nmcli connection show lte-modem               # профиль модема
# проверить переключение (45 с считаем, что через Wi-Fi интернета нет):
sudo systemctl stop internet-failover
sudo timeout 45 python3 ~/project/modem/failover.py --simulate-wifi-down
sudo systemctl start internet-failover        # вернёт модем в резерв
```

## Файлы

| Файл | Что это |
|---|---|
| `failover.py` | сторож резервного канала |
| `internet-failover.service` | юнит, установлен в `/etc/systemd/system/` |

Профиль NetworkManager лежит в `/etc/NetworkManager/system-connections/lte-modem.nmconnection`.

## Второй модем

**Huawei E3372h / МегаФон M150-2** (stick-прошивка 21.200, тоже разлочен) сам интернет не поднимает
и зависает через пару секунд после подключения: в нём повреждён образ виртуального CD
(внутри — недопрошитый веб-интерфейс HiLink). Для Pi не используется.
