# webcam — панель дома

Веб-панель на Pi, без входа (она только в локальной сети): **Камера**, **Устройства**
(Home Assistant) или **Zigbee** (Zigbee2MQTT). Адрес: `http://10.20.0.1:45461/` из Wi-Fi «PiHome»
или `http://10.10.0.1:45461/` по кабелю — см. `../network/README.md`.

## Панель

- **Вход выключен**: панель видна только в Wi-Fi Pi, по кабелю и через ZeroTier и открывается сразу —
  вместе с Home Assistant. Отвечает она только на свой IP и локальные имена (`pi.lan`,
  `raspberry.local`, `localhost`): запрос с чужим именем в `Host` получает 403. Это защита от
  DNS rebinding — когда чужой сайт в браузере пытается обращаться к панели как к себе.
  **Включить вход снова**: раскомментировать `WEBCAM_AUTH=логин:пароль` в `webcam.env` и
  `sudo systemctl restart webcam`. Тогда — форма входа, «Запомнить меня» (30 дней, без галочки — сутки),
  блокировка на минуту после 5 неверных паролей, сессии в `sessions.json` (только хеши) и HTTP Basic
  для VLC и скриптов: `http://логин:пароль@10.20.0.1:45461/stream.mjpg`.
- **Шапка**: кнопка **«Настройка zapret»** открывает отдельную панель обхода блокировок
  (порт 45464, окно `pi-zapret`, см. `../zapret/README.md`); точка на ней — работает ли обход.
- **Главная** (`/`): плитки с состоянием камеры (живая миниатюра), Home Assistant и Zigbee.
  Каждая плитка открывается в своей вкладке, а повторный клик возвращает в уже открытую
  (именованные окна `pi-camera`, `pi-zigbee`; у HA — `ha-main-window`, так HA сам называет своё окно).
  «Все записи» и «Открыть в записях» тоже ведут во вкладку камеры. «←» на странице камеры закрывает
  её вкладку, если она открыта с главной, иначе — переход на главную.
  Под ними — **трей**: значки разделов «Движение», «Интернет», «Wi-Fi», «Raspberry Pi» с кратким
  состоянием на каждом (идёт ли запись, есть ли интернет, сколько устройств в Wi-Fi, температура и CPU).
  Клик по значку плавно раскрывает раздел, кнопка ⌃ в его углу сворачивает обратно. По умолчанию всё
  свёрнуто; что раскрыто, браузер запоминает (localStorage), а `/#wifi`, `/#internet`, `/#events`,
  `/#system` в адресе раскрывают нужный раздел сразу.
  Раздел **«SMS»** — оповещения через модем (пропадало питание, холодно у датчика, движение у камеры):
  номера, что включено, датчики температуры, проверочное SMS и последние отправленные. Шлёт их
  отдельный сервис `sms-alerts`, см. `../alerts/README.md`.
  Внизу, в отдельной рамке, — **мониторинг Pi** (обновление раз в 3 с): температура со статусом
  (до 70 °C норма, 70–80 горячо, от 80 перегрев — Pi сбрасывает частоту), загрузка CPU и по ядрам,
  load average, частота, память, диск, сеть, троттлинг и питание (`vcgencmd get_throttled`),
  графики температуры и загрузки за 10 минут (наведите курсор или стрелками — значения по времени),
  пять самых нагружающих процессов. Данные снимает `sysmon.py`, отдаёт `/api/system`.
- **Движение** (на главной, под плитками): 5 последних событий — миниатюра, время, длительность,
  сколько роликов. Клик открывает плеер прямо на главной; части длинного события идут подряд.
  Ролики одного движения помечены общим id события (`recordings/.events.json`).
- **Интернет** (на главной): LTE-модем (состояние и управление), Wi-Fi Pi — точка доступа и сколько
  в ней устройств — и кабель; подробнее `../modem/README.md` и `../network/README.md`.
  Данные — `/api/internet`, команды — `POST /api/modem/{data,mode,reconnect,reboot}` (только JSON).
- **Wi-Fi** (на главной): точка доступа Pi — имя сети, канал, сколько устройств, скорость и трафик;
  таблица устройств (имя из DHCP, IP и MAC, сигнал, скорость связи, текущая скорость, трафик,
  сколько в сети), **QR-код для подключения** (наводишь камеру телефона — iPhone и Android подключаются
  сами; строится на Pi, интернет не нужен) и настройки: имя сети, пароль, диапазон 2,4 / 5 ГГц и канал. Сохранение
  перезапускает Wi-Fi на несколько секунд; если точка доступа с новыми настройками не включилась,
  панель сама вернёт прежние. Код — `wifi.py` (NetworkManager через `sudo -n`, `iw`, аренды dnsmasq),
  данные — `/api/wifi`, QR-код — `/wifi-qr.svg`, настройки — `POST /api/wifi` (только JSON).
- **AdGuard Home** (на главной): блокировка рекламы и трекеров для устройств в Wi-Fi Pi — защита
  (вкл / пауза 10 мин или час, потом включается сама), запросов и блокировок за сутки, средний ответ DNS,
  график по часам, что чаще блокируется, кто больше всех обращается; кнопка «Открыть AdGuard Home».
  Сам AdGuard Home — на порту **45463** через панель (пароль подставляет панель), подробнее —
  `../adguard/README.md`. Код — `adguard.py`, данные — `/api/adguard`, команды — `POST /api/adguard`
  (`{"action": "pause", "minutes": 10|60}` или `{"action": "resume"}`; JSON).
- **Bluetooth** (на главной): адаптер Pi; **мои устройства** (сопряжённые — подключить, отключить, забыть,
  заряд батареи); **датчики** — показания BLE-датчиков, которые панель расшифровывает сама (BTHome, Xiaomi
  в том числе с прошивкой pvvx/ATC, Qingping, Govee, SwitchBot; зашифрованные Xiaomi — только через Home Assistant
  с ключом); **рядом** — найденные поиском (30 с), безымянные маячки спрятаны под кнопку. «Подключить» =
  сопряжение + «доверять» + подключение; если устройство просит код (клавиатура, телефон), панель его
  показывает. Сопряжение, начатое не из панели, Pi отклоняет. Тем же адаптером пользуется Home Assistant:
  BlueZ делит его, наш поиск включается поверх поиска HA и не мешает ему; датчики для автоматизаций HA
  находит сам (ссылка «добавить в Home Assistant»). Код — `bt.py` (BlueZ по D-Bus) и `ble_sensors.py`,
  данные — `/api/bluetooth`, команды — `POST /api/bluetooth` (`scan`, `connect`, `disconnect`, `forget`; JSON).
- **Камера** (`/camera`): см. ниже.
- **Устройства**: Home Assistant на порту **45462**. HA слушает только localhost, панель проксирует
  туда запросы (вместе с WebSocket), и HA пускает их без своего логина (если вход в панель включён —
  только вошедших).
  Подробнее — `../homeassistant/README.md`.
- **Zigbee** (`/z2m/`): интерфейс Zigbee2MQTT через тот же прокси. Пока адаптер не вставлен,
  там подсказка, что его нужно подключить. Подробнее — `../zigbee/README.md`.

## Доступ извне — ZeroTier

Pi в частной сети ZeroTier (её ID — `sudo zerotier-cli listnetworks`, управление — https://my.zerotier.com), адрес Pi в ней
**10.220.183.143**. С любого своего устройства, подключённого к этой сети (приложение ZeroTier One,
устройство нужно подтвердить галочкой Auth в Members):

- панель: http://10.220.183.143:45461
- Home Assistant: http://10.220.183.143:45462

Работает через любой NAT и CGNAT, в том числе когда Pi на резервном LTE (проверено: Wi-Fi выключен —
через ~30 с сторож переводит интернет на модем, ZeroTier остаётся на связи с тем же адресом, панель, HA
и камера доступны). На главной, в доске «Интернет», — блок **ZeroTier**: состояние, адрес Pi, ссылки,
подключённые устройства (задержка, напрямую или через ретранслятор) и трафик (`zt.py`, локальный API
ZeroTier 127.0.0.1:9993; токен — копия authtoken.secret в `~/.zeroTierOneAuthToken`, права 600). Из открытого интернета
панель не видна. Сервис `zerotier-one` в автозапуске; `sudo zerotier-cli listnetworks` — состояние.
(Прямой доступ по IP невозможен: у МТС CGNAT, дома двойной NAT; Cloudflare Tunnel из этой сети режется.)

Код: `webcam.py` (сервер и камера), `auth.py` (вход и сессии), `panel.py` (прокси и состояние
сервисов), `pages/` (страницы).

# Камера

## Что умеет

- **Эфир**: живое видео с выбором качества (1080p, 540p, 360p) и звук с микрофона камеры
  (кнопка «Звук»). Выбранное качество запоминается в браузере.
- **Записи**: ролики по дням с миниатюрами и встроенным плеером (перемотка, скачивание,
  переход к следующему ролику).
- **Запись по движению**: камера работает постоянно, последние 15 секунд видео и звука держатся
  в памяти. Как только в кадре появляется движение, пишется ролик на 60 секунд: первые 15 секунд —
  то, что было до движения. Если движение не прекращается, сразу пишется следующий ролик без
  пропуска кадров.
- Камера и её микрофон находятся автоматически (микрофон — ALSA-устройство на том же USB).
  Если камеру переподключить, всё восстановится само.
- Когда папка с роликами превышает лимит (20 ГБ), самые старые ролики удаляются.

## Как устроено

Всё работает на GStreamer внутри одного процесса Python:

- Камера отдаёт готовый MJPEG, кадры идут в эфир 1080p и в детектор движения без перекодирования.
- Звук: `alsasrc` 48 кГц → 24 кГц моно. У видео и звука общие системные часы, поэтому в роликах
  они синхронны.
- Ролики: JPEG декодирует libjpeg-turbo (`jpegdec`), H.264 кодирует аппаратный кодировщик Pi
  (`v4l2h264enc`), звук — AAC. MP4 1080p30 8 Мбит/с, ~58 МБ в минуту.
  Во время записи процесс занимает ~1 ядро из 4, без записи — несколько процентов.
- 540p и 360p для эфира пережимаются, только пока их кто-то смотрит (~0,5 ядра каждое).
- Аппаратный JPEG-декодер Pi (`v4l2jpegdec`) не используется: с этой камерой он зависает.

Пакеты: `gstreamer1.0-tools`, `gir1.2-gstreamer-1.0`, `gir1.2-gst-plugins-base-1.0`,
`gstreamer1.0-plugins-{base,good,bad}`, `gstreamer1.0-libav`, `python3-gi`, `python3-numpy`, `python3-pil`.

## Камера в Home Assistant

- **Видео**: интеграция «MJPEG IP Camera» → `camera.kamera`. Поток
  `http://127.0.0.1:45461/stream.mjpg?q=540p`, снимки `snapshot.jpg`, вход по логину панели (Basic).
- **Датчики** (MQTT discovery, устройство «Камера»): `binary_sensor.kamera_dvizhenie` (движение),
  `binary_sensor.kamera_zapis` (идёт запись), `binary_sensor.kamera_sviaz` (камера на связи).
  Публикует `ha_mqtt.py` в топики `webcam/*`; если панель упадёт, брокер объявит их недоступными.
- **Записи**: в HA «Мультимедиа → My media → Камера» — папка `recordings/` смонтирована
  в контейнер только для чтения (`/media/Камера`).
- **Готовый ролик**: сообщение в `webcam/clip` с `{"name": "ДАТА/ВРЕМЯ.mp4", "path": "..."}` —
  на него можно повесить автоматизацию (триггер «MQTT»).

Пример автоматизации: «Движение → уведомление на телефон со снимком» — триггер
`binary_sensor.kamera_dvizhenie` = «Обнаружено», действие `camera.snapshot` + уведомление.

## Отправка в хранилище

`--on-clip КОМАНДА` (или `WEBCAM_ON_CLIP` в `webcam.env`) запускается после каждого готового ролика
с путём к `.mp4` последним аргументом. Например:

```sh
WEBCAM_ON_CLIP=rclone copy --no-traverse remote:webcam
```

## Адреса

- `/`: главная, `/login`, `/logout`
- `/camera`: камера (`#live` — эфир, `#rec` — записи, `#rec/ДАТА/ВРЕМЯ.mp4` — конкретный ролик)
- `/api/overview`: состояние камеры, HA и Zigbee для главной
- `/api/system`: мониторинг Pi (текущие значения и история)
- `/api/internet`: каналы интернета и модем
- `/api/adguard`: AdGuard Home — защита, статистика за сутки, топы
- `/api/bluetooth`: адаптер, устройства, показания датчиков, ход команды (`job`)
- `/api/wifi`: точка доступа, устройства в ней, настройки и ход их применения (`job`)
- `/z2m/`: Zigbee2MQTT
- `/stream.mjpg?q=1080p|540p|360p`: живой поток (открывается и в VLC, `mpv`)
- `/audio.pcm`: живой звук, сырой PCM S16LE моно 24 кГц
- `/snapshot.jpg`: один кадр (`?small=1` — уменьшенный)
- `/status`: состояние в JSON (движение, `motion_level` — сколько % кадра меняется, идёт ли запись)
- `/recordings.json`: список роликов
- `/recordings/ДАТА/ВРЕМЯ.mp4`: сам ролик

## Управление

```sh
sudo systemctl status webcam      # состояние
sudo systemctl restart webcam     # перезапуск (например, после смены пароля)
journalctl -u webcam -f           # логи: движение, запись, удаление старых роликов
./webcam.py --list                # какие камеры видны, их форматы и микрофоны
```

## Настройки

Все параметры: `./webcam.py --help`. Для сервиса допиши флаги в `ExecStart` в
`/etc/systemd/system/webcam.service`, затем `sudo systemctl daemon-reload && sudo systemctl restart webcam`.

| Флаг | По умолчанию | |
|---|---|---|
| `--port` | 45461 | порт панели |
| `--ha-port` | 45462 | порт, на котором панель отдаёт Home Assistant |
| `--adguard-port` | 45463 | порт, на котором панель отдаёт AdGuard Home |
| `--size` / `--fps` | 1920x1080 / 30 | |
| `--clip` | 60 | длина ролика, сек |
| `--preroll` | 15 | сколько секунд до движения попадает в ролик |
| `--motion-area` | 1.0 | какой % кадра должен измениться; меньше — чувствительнее |
| `--bitrate` | 8M | битрейт видео в записи |
| `--max-storage-gb` | 20 | лимит папки с роликами |
| `--record-dir` | ./recordings | |
| `--device` | автопоиск | конкретная `/dev/videoN` |
| `--audio-device` / `--no-audio` | автопоиск | микрофон вручную (`hw:3,0`) или без звука |
| `--mqtt` / `--no-mqtt` | localhost:1883 | брокер для датчиков в HA |

Качество эфира задаётся в `QUALITIES` в начале `webcam.py`.
