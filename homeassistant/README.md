# homeassistant

Home Assistant для устройств по Wi-Fi, Bluetooth и Zigbee. Открывается из панели:
плитка «Устройства» на главной, или `http://10.20.0.1:45462/`.

## Как устроено

- Контейнер Docker `homeassistant` (`compose.yaml`), данные в `config/`. Часовой пояс — в `.env`
  рядом с `compose.yaml` (`TZ=Asia/…`); docker compose читает его сам, в репозиторий он не входит.
- Сеть хоста: HA сам находит Wi-Fi-устройства в локальной сети (mDNS, SSDP).
- Bluetooth: через BlueZ на Pi (`/run/dbus` проброшен в контейнер).
- Zigbee: через Zigbee2MQTT и MQTT, см. `../zigbee`.
- HA слушает только `127.0.0.1:8123`. Снаружи он доступен через панель на порту 45462:
  она проксирует запросы в HA (пока вход в панель выключен — от всех в локальной сети). Такие запросы
  приходят с 127.0.0.1, поэтому HA пускает без своего логина (`trusted_networks` в `configuration.yaml`).

- Записи камеры: `~/project/webcam/recordings` смонтирована в контейнер только для чтения как
  `/media/Камера` — видно в «Мультимедиа → My media → Камера». Удалять ролики из HA нельзя,
  старые чистит сама панель по лимиту.

## Первый запуск

1. Главная панели → «Устройства». HA попросит создать владельца (имя, логин, пароль),
   указать дом на карте, часовой пояс и единицы измерения.
2. Настройки → Устройства и службы → «Добавить интеграцию» → **MQTT** → брокер `localhost`,
   порт `1883`, без логина. После этого Zigbee-датчики из Zigbee2MQTT появятся в HA сами.
3. Bluetooth HA найдёт сам (встроенный адаптер Pi), Wi-Fi-устройства — в «Обнаруженных».

## Управление

```sh
cd ~/project/homeassistant
sudo docker compose ps                 # состояние
sudo docker compose logs -f            # логи
sudo docker compose restart            # перезапуск
sudo docker compose pull && sudo docker compose up -d   # обновление
```
