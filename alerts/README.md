# alerts — SMS-оповещения

Сервис `sms-alerts` шлёт SMS через LTE-модем (мобильный интернет не нужен, только SIM в сети):

```
Pi: пропадало питание 07.10 14:32–15:10 (38 мин). Работает.
Pi: холодно — Подвал −1,5 °C (порог 0 °C), 08.10 03:15.
Pi: Подвал снова +1,2 °C, 08.10 09:40.
Pi: датчик Подвал молчит 2 ч, последний раз +3 °C, 08.10 11:00.
Pi: движение у камеры, 08.10 14:05.
```

## Настройка — в панели

Раздел **«SMS»** на главной: номера (до 5), проверочное SMS, что включено — питание, холод,
движение — и их параметры, датчики температуры, последние отправленные SMS и очередь.

Настройки лежат в `settings.json` (рядом, **не в репозитории** — там номера); сервис перечитывает
файл сам. Формат и проверка — `sms_settings.py`. По умолчанию: питание и холод включены (порог 0 °C,
но датчик надо отметить), движение выключено.

## Питание

Раз в минуту сервис отмечает в `/var/lib/sms-alerts/state.json`, что Pi жива, а при штатном
выключении записывает «выключились чисто». Нет такой отметки после загрузки — питание пропало
внезапно: последняя отметка ≈ когда пропал свет, загрузка ≈ когда он вернулся. Штатные
`poweroff` и `reboot` SMS не вызывают; зависание или выдернутый кабель выглядят как пропажа света.

- **Точное время.** Своих часов у Pi нет: после загрузки время верное только после синхронизации
  по NTP (через модем). SMS ждёт её до 10 минут, не дождался — шлёт без времени включения
  («пропадало питание с 07.10 14:32»). `≈` — часы и до отключения не были синхронизированы.
- Пропадал свет несколько раз, пока SMS не ушло, — придёт одно: «питание пропадало 3 раза, последний …».

## Температура

Подходит датчик **Zigbee** (показания из MQTT от Zigbee2MQTT) или **Bluetooth** (из панели — она
расшифровывает Xiaomi, pvvx/ATC, BTHome, Qingping, SwitchBot, Govee). Все замеченные датчики
с температурой сервис показывает в панели — следит только за отмеченными, так что соседские
Bluetooth-датчики за стеной не мешают.

- Холоднее порога дольше 5 минут — SMS; один выброс не считается.
- «Снова тепло» — когда на 1 °C теплее порога, чтобы у самой границы SMS не сыпались туда-сюда.
- Датчик молчит дольше заданного (по умолчанию 2 ч) — SMS: на морозе первыми садятся батарейки.
  Bluetooth-датчик «замолкает», когда пропадает из списка BlueZ (через ~30 с без рекламы).

## Движение

Панель публикует в MQTT `webcam/motion`; на начало движения — SMS, но не чаще заданной паузы
(по умолчанию раз в 30 минут). Ролики — в панели, раздел «Движение».

## Очередь

Нет SIM или сети — SMS ждут в `state.json` и повторяются через 30 с … 10 мин, в том числе после
перезагрузки (копится не больше 20, старые выбрасываются). Кириллица — 70 символов на SMS;
сообщения рассчитаны на одно SMS.

## Установка

```sh
sudo cp ~/project/alerts/sms-alerts.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now sms-alerts
```

Дальше — номер и что включить в панели, раздел «SMS».

## Проверка

```sh
cd ~/project/alerts
python3 alerts.py --status     # настройки, состояние, очередь, замеченные датчики
python3 alerts.py --test       # проверочное SMS (то же, что кнопка в панели)
journalctl -u sms-alerts -f
python3 -m unittest discover -s tests
```

## Файлы

| Файл | Что это |
|---|---|
| `alerts.py` | сервис |
| `sms_settings.py` | настройки: умолчания, проверка, чтение и запись (им же пользуется панель) |
| `sms-alerts.service` | юнит, установлен в `/etc/systemd/system/` |
| `settings.json` | номера и что включено (**не в репозитории**), меняется из панели |

Отправка SMS — `HiLink.send_sms` в `../webcam/modem.py`, раздел в панели — `../webcam/sms.py`.
