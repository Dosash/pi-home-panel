# adguard — блокировка рекламы и трекеров

AdGuard Home отвечает на DNS-запросы устройств в Wi-Fi Pi («PiHome») и не пускает их к рекламе,
трекерам и вредоносным сайтам. Наружу DNS идёт по шифрованному DoH — оператор (МТС) не видит
и не подменяет запросы.

Открывается из панели: главная → значок **AdGuard** в трее → «Открыть AdGuard Home», или
`http://10.20.0.1:45463/`. Пароль не нужен — его подставляет панель (как с Home Assistant).
В самой панели — статистика за сутки, график по часам, что чаще блокируется, кто больше всех
обращается, и пауза защиты на 10 минут или час (если какой-то сайт перестал работать).

## Как устроено

```
устройство в Wi-Fi ──DNS──► AdGuard Home :53 ──DoH──► Google / Cloudflare / Quad9
                                  │                    (если все молчат: Yandex DoH, потом DNS модема)
                                  └── *.lan и обратные запросы ──► dnsmasq 10.20.0.1:5354
```

- Программа: `/opt/AdGuardHome` (версия v0.107.79, с GitHub, SHA-256 сверен), служба `AdGuardHome`.
  Настройки — `/opt/AdGuardHome/AdGuardHome.yaml` (root), данные (статистика, журнал) — `/opt/AdGuardHome/data/`.
- DNS: все адреса Pi, порт 53. Веб и API — только `127.0.0.1:3080`, снаружи — через панель (порт 45463),
  которая пускает только по IP Pi или локальному имени (защита от DNS rebinding) и подставляет пароль.
- Пароль администратора — `adguard.env` здесь (`ADGUARD_AUTH=admin:…`, права 600). Его читает панель.
- dnsmasq от NetworkManager раздаёт адреса (DHCP) и в DHCP называет DNS-сервером `10.20.0.1`,
  а сам отвечает на порту 5354 только про локальное: `pi.lan` и имена устройств. AdGuard спрашивает
  у него обратные записи — поэтому в статистике видны имена устройств, которые их сообщают
  (телефоны со «случайным MAC» имени не передают — они видны по IP). См. `../network/dnsmasq-shared.conf`.
- Кабель (eth0) DNS не получает — компьютер по кабелю ходит в интернет своим путём.
- Фильтры: AdGuard DNS filter, HaGeZi's Normal (реклама, трекеры), Dandelion Sprout's Anti-Malware;
  обновляются раз в сутки. Кэш оптимистичный: на медленном LTE ответ отдаётся сразу из кэша,
  а запись обновляется в фоне.
- Журнал запросов хранится 7 дней, статистика — сутки.

## Управление

```sh
sudo systemctl status AdGuardHome        # состояние
sudo journalctl -u AdGuardHome -f        # логи
sudo systemctl restart AdGuardHome
cat ~/project/adguard/adguard.env        # пароль администратора (логин admin)
```

Сайт не открывается из-за блокировки — проще всего пауза из панели; насовсем — в AdGuard Home:
«Журнал» → найти домен → «Разблокировать».

Обновление: AdGuard Home сам сообщает о новой версии в своём интерфейсе (кнопка «Обновить»).

Вернуть DNS как было (без AdGuard): `sudo systemctl disable --now AdGuardHome`, а в
`../network/dnsmasq-shared.conf` убрать `port=5354`, `local=/lan/`, `domain=lan` и строку
`dhcp-option=tag:wlan0,option:dns-server,…`, установить его и перезапустить профили (см. `../network/README.md`).
